8 · 能力边界：已有业务 vs 管理端新增
小程序已有业务能力 ≠ 管理接口已实现；未建设的一律明确标注，不伪装成已上线
能力状态说明
微信登录、昵称头像小程序已有管理端仅展示注册时间、昵称等概况；OpenID 默认脱敏。
收入 / 支出记录小程序已有管理端拟新增只读查询与授权查看；原型仅演示遮蔽，真实权限及审计尚未实现。
多账本、自定义分类小程序已有账本可查询并下钻记录；自定义分类只读。
统计、月度预算小程序已有管理端只读查询，所有预算入口默认遮蔽金额，按条授权显示，不重算统计。
用户 / 账本 / 记录 / 预算查询接口拟新增本原型定义了字段与筛选，接口待开发。
系统预置分类维护拟新增新增 / 编辑 / 排序 / 启停，停用不删除历史。
操作日志拟建设采集登录、查询、敏感查看、分类维护；接口未接入。
系统状态监测拟建设后端 / 数据库探针待接；Redis 未接入则显示未接入。
批量导出个人信息明确不做第一版不提供，后续如有合规需求需单独评审。
改写用户账单 / 一键删除用户数据明确不做管理端只读排查，避免误操作用户财务数据。
反馈列表 / 工单 / 在线客服明确不做使用微信原生反馈能力，仅提供后台指引。
订单 / 商品 / 支付 / 提现 / 营销明确不做与记账小程序业务无关，不设计。
重启服务器 / 执行 SQL / 改生产配置明确不做系统状态为只读页，高危操作走内部运维流程。
9 · 安全与合规说明
管理员权限必须由服务端鉴权：前端隐藏菜单 / 按钮不构成访问控制，所有管理接口需在服务端校验管理员身份与权限，未授权请求应返回 403 并提示「无访问权限」。
敏感信息最小必要：OpenID 默认脱敏；流水金额、备注和预算金额默认遮蔽。选定用途后仅显示一条，可重新隐藏；查询、切换页签或刷新后清除展示授权。正式服务端应在返回明文前完成鉴权和审计，原型的前端遮蔽不是安全措施。
数据诚实：未接入的指标与模块显示「待接入 / 拟建设」，不用占位数据伪装实时结果；不把用户收支金额汇总包装为平台营收。
10 · 开发验收清单

当前交付是静态交互原型，不是正式管理端。样例数据、登录和监测均为演示；正式前端工程、管理 API、鉴权与审计须分别开发和验收。

  • 桌面宽度 1280 / 1440 / 1920 下无整页横向溢出；折叠菜单具有名称提示。
  • 用户详情进入记录或预算时，正确打开页签并带入用户、账本或月份条件。
  • 授权用途必填，“其他”须填写说明；取消不显示数据；隐藏、切换、查询及刷新可清除显示状态。
  • 弹窗和抽屉进入时获得焦点；Tab 在弹层内循环；Esc、取消或遮罩关闭后恢复焦点。
  • 分类名称校验长度与同类型重复项，排序为 1–99 整数；编辑保存图标，停用必须确认。
  • 登录缺项、错误和会话过期有清晰反馈；演示登录不提供真实访问控制。
  • 列表覆盖加载、有数据、无匹配、空数据、失败重试和无权限；监测未知不冒充正常。
